# The QCP User Manual

**Qualified C Programming (QCP)** lets you prove that a C function does what its specification says. You annotate ordinary C with a spec — a precondition, a postcondition, and (for loops) an invariant — written in `/*@ ... @*/` comments; QCP symbolically executes the code against that spec and discharges the resulting proof obligations, most of them automatically.

**You do not need a background in separation logic, Rocq (formerly Coq), or symbolic execution to start.** A C programmer can write specs and watch them go green at "autopilot," letting the tool and an optional LLM do the proving. The theory is here when you want it — to turn the automation up, to read a proof, or to understand *why* a green check is a strong guarantee — but it is strictly **opt-in**. Start at [ch 4](ch04-quickstart-stage-a.md) and reach for the rest as questions come up.

> This manual documents **QCP v2.0.3** against **Rocq 8.20.1** (snapshot at commit `9804a85`). The generated proofs under `SeparationLogic/examples/` are regenerated by the tooling, so any count here is an approximate snapshot — where a number matters, the manual gives you the command to re-measure it yourself.
